## 개요

**A*(A-Star, 에이스타) 알고리즘**은 시작점에서 목표점까지의 최단 경로를 찾는 탐색 알고리즘이다. 게임의 캐릭터 이동이나 격자 지도의 길 찾기처럼 목표 위치를 알고 있는 문제에 활용할 수 있다.

시작점에서 지금까지 이동한 비용에 **목표까지 남은 비용의 추정값**을 더하여, 전체 비용이 작을 것으로 예상되는 경로부터 탐색한다. 이 추정값을 **휴리스틱(Heuristic)**이라고 한다.

휴리스틱을 적절하게 정하면 탐색 범위를 줄일 수 있다. 다만 어떤 휴리스틱을 사용하더라도 최단 경로가 보장되는 것은 아니므로, 이동 규칙과 휴리스틱의 조건을 함께 확인해야 한다.

## 핵심 아이디어

A*는 다음 평가 함수의 값이 가장 작은 후보를 먼저 선택한다.

```text
f(n) = g(n) + h(n)
```

| 값 | 의미 |
|----|----|
| `g(n)` | 지금까지 발견한 경로 중 시작점에서 노드 `n`까지 도달하는 최소 비용 |
| `h(n)` | 노드 `n`에서 목표점까지 남은 비용의 추정값 |
| `f(n)` | 노드 `n`을 거쳐 목표점에 도달할 때의 예상 전체 비용 |

예를 들어 후보 A의 `g = 4`, `h = 3`이면 `f = 7`이고, 후보 B의 `g = 2`, `h = 6`이면 `f = 8`이다. 이때 A*는 A를 먼저 탐색한다. 현재까지 이동한 비용뿐 아니라 앞으로 이동할 비용도 고려하기 때문이다.

`h(n) = 0`으로 두면 `f(n) = g(n)`이 되어 다익스트라 알고리즘과 같은 비용 기준으로 탐색한다. 반대로 `g(n)`을 제외하고 `h(n)`만 비교하면 탐욕적 최선 우선 탐색(Greedy Best-First Search)이 된다. [UC Berkeley CS 188 — Informed Search](https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html)

## 휴리스틱과 최단 경로

### 맨해튼 거리

상하좌우로만 이동하고 한 칸의 이동 비용이 `1`인 격자에서는 **맨해튼 거리**를 사용할 수 있다.

```text
h(n) = |현재 X - 목표 X| + |현재 Y - 목표 Y|
```

예를 들어 `(1, 2)`에서 `(4, 4)`까지의 맨해튼 거리는 `3 + 2 = 5`이다. 장애물을 무시했을 때 필요한 이동 횟수이므로, 장애물을 피해 가는 실제 최단 비용보다 커지지 않는다.

### 허용 가능성과 일관성

휴리스틱을 사용할 때는 다음 두 성질을 구분한다.

| 성질 | 조건 | 의미 |
|----|----|----|
| 허용 가능성(Admissibility) | `0 <= h(n) <= 실제 남은 최단 비용` | 남은 비용을 과대평가하지 않는다. |
| 일관성(Consistency) | `h(n) <= cost(n, next) + h(next)` | 이웃으로 한 번 이동할 때 휴리스틱이 줄어드는 양은 이동 비용 이하이다. |

목표점에서는 `h(goal) = 0`으로 둔다. 일관성을 만족하면 허용 가능성도 만족하며, 노드를 최소 `f` 후보로 꺼내 확장했을 때 그 노드까지의 최단 비용이 확정된다. 이미 확장한 노드를 다시 처리하지 않는 구현에서는 이 성질이 중요하다. [CMU 15-281 — Search](https://www.cs.cmu.edu/~15281/coursenotes/search/)

허용 가능하지만 일관적이지 않은 휴리스틱을 사용한다면, 더 작은 `g`를 발견했을 때 이미 확장한 노드도 다시 탐색할 수 있어야 한다.

아래 예제의 맨해튼 거리는 한 칸 이동할 때 최대 `1`만큼 줄어들고 이동 비용도 `1`이므로 두 조건을 모두 만족한다.

## 동작 과정

1. 시작점의 `g`를 `0`으로 설정하고, 탐색 후보를 보관하는 **Open Set**에 넣는다.
2. 후보 중 `f = g + h`가 가장 작은 노드를 꺼낸다.
3. 더 좋은 경로가 이미 발견되어 오래된 후보라면 건너뛴다.
4. 꺼낸 노드가 목표점이면 이전 노드를 역추적하여 경로를 반환한다.
5. 이동 가능한 이웃마다 `새로운 g = 현재 g + 이동 비용`을 계산한다.
6. 처음 발견한 이웃이거나 기존 `g`보다 작다면 비용과 이전 노드를 갱신하고 후보에 넣는다.
7. 후보가 모두 소진될 때까지 목표점에 도달하지 못했다면 경로가 없는 것이다.

**목표점을 이웃으로 발견한 순간이 아니라, 우선순위 큐에서 유효한 최소 `f` 후보로 꺼낸 순간에 종료한다.** 처음 발견한 목표 경로보다 비용이 작은 경로가 아직 후보에 남아 있을 수 있기 때문이다.

## C# 예제: 장애물이 있는 격자

다음 지도에서 `S`는 시작점, `G`는 목표점, `#`은 벽, `.`은 이동 가능한 칸이다. 좌표는 왼쪽 위가 `(0, 0)`이며, 오른쪽으로 갈수록 `X`, 아래로 갈수록 `Y`가 증가한다.

```text
S . # . .
# . # . #
. . . . #
. # # # #
. . . . G
```

예제의 조건은 다음과 같다.

- 상하좌우 네 방향으로 이동하며 모든 이동 비용은 `1`이다.
- `grid`는 각 행의 길이가 같은 직사각형 지도이며, 배열과 각 행은 `null`이 아니라고 가정한다.
- 시작점과 목표점은 좌표로 전달한다. 지도에 표시된 `S`, `G` 문자를 별도로 검색하지 않는다.
- 경로는 시작점과 목표점을 모두 포함한다. 경로가 없거나 두 좌표 중 하나가 지도 밖 또는 벽이면 빈 리스트를 반환한다.

**.NET 6 이상**의 콘솔 프로젝트에서 `Program.cs`를 아래 코드로 바꾸어 실행할 수 있다. `PriorityQueue`는 .NET 6에 추가된 자료구조로, 우선순위 값이 작은 항목부터 꺼내므로 `f`를 그대로 우선순위로 사용한다. [Microsoft Learn — PriorityQueue](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-6#priorityqueue-class)

```cs
using System;
using System.Collections.Generic;

string[] grid =
{
    "S.#..",
    "#.#.#",
    "....#",
    ".####",
    "....G"
};

var path = FindPath(grid, (0, 0), (4, 4));

if (path.Count == 0)
{
    Console.WriteLine("경로가 없습니다.");
}
else
{
    Console.WriteLine($"이동 횟수: {path.Count - 1}");
    Console.WriteLine(string.Join(" -> ", path));
}

static List<(int X, int Y)> FindPath(
    string[] grid,
    (int X, int Y) start,
    (int X, int Y) goal)
{
    int height = grid.Length;
    int width = height == 0 ? 0 : grid[0].Length;

    bool IsWalkable((int X, int Y) point) =>
        point.X >= 0 && point.X < width &&
        point.Y >= 0 && point.Y < height &&
        grid[point.Y][point.X] != '#';

    int Heuristic((int X, int Y) point) =>
        Math.Abs(point.X - goal.X) + Math.Abs(point.Y - goal.Y);

    if (!IsWalkable(start) || !IsWalkable(goal))
        return new List<(int X, int Y)>();

    // 후보에는 좌표와 큐에 넣을 당시의 g를 함께 저장한다.
    var open = new PriorityQueue<((int X, int Y) Position, int G), int>();
    var gScore = new Dictionary<(int X, int Y), int>();
    var cameFrom = new Dictionary<(int X, int Y), (int X, int Y)>();

    (int X, int Y)[] directions =
    {
        (1, 0), (-1, 0), (0, 1), (0, -1)
    };

    gScore[start] = 0;
    open.Enqueue((start, 0), Heuristic(start));

    while (open.Count > 0)
    {
        var entry = open.Dequeue();
        var current = entry.Position;

        // 이후에 더 짧은 경로가 발견되었다면 오래된 후보이다.
        if (entry.G != gScore[current])
            continue;

        if (current == goal)
        {
            var result = new List<(int X, int Y)> { current };

            while (current != start)
            {
                current = cameFrom[current];
                result.Add(current);
            }

            result.Reverse();
            return result;
        }

        foreach (var direction in directions)
        {
            var next = (
                X: current.X + direction.X,
                Y: current.Y + direction.Y);

            if (!IsWalkable(next))
                continue;

            int newG = entry.G + 1;

            // 같은 비용으로 다시 도달한 경우에도 갱신하지 않는다.
            if (gScore.TryGetValue(next, out int oldG) && newG >= oldG)
                continue;

            gScore[next] = newG;
            cameFrom[next] = current;
            open.Enqueue((next, newG), newG + Heuristic(next));
        }
    }

    return new List<(int X, int Y)>();
}
```

### 실행 결과

```text
이동 횟수: 10
(0, 0) -> (1, 0) -> (1, 1) -> (1, 2) -> (0, 2) -> (0, 3) -> (0, 4) -> (1, 4) -> (2, 4) -> (3, 4) -> (4, 4)
```

경로를 `*`로 표시하면 다음과 같다.

```text
S * # . .
# * # . #
* * . . #
* # # # #
* * * * G
```

시작점의 맨해튼 거리는 `8`이지만 벽을 우회해야 하므로 실제 최단 경로는 `10`번의 이동이 필요하다. 경로에 담긴 좌표는 `11`개이며, 이동 횟수는 `path.Count - 1`이다. 시작점과 목표점이 같은 이동 가능한 칸이면 좌표 하나를 반환하므로 이동 횟수는 `0`이다.

### 구현에서 확인할 부분

| 자료구조 | 역할 |
|----|----|
| `open` | `f`가 작은 탐색 후보를 먼저 꺼내는 우선순위 큐 |
| `gScore` | 각 좌표까지 발견한 최소 이동 비용 |
| `cameFrom` | 최소 비용 경로에서 바로 이전에 방문한 좌표 |

이 구현은 큐에 들어 있는 항목의 우선순위를 직접 수정하는 대신, 더 좋은 경로를 발견하면 새 항목을 추가한다. 같은 좌표가 큐에 여러 번 들어갈 수 있으므로, 꺼낸 항목의 `G`와 최신 `gScore`를 비교하여 오래된 항목을 건너뛴다.

또한 방문 여부만으로 재탐색을 막는 별도의 **Closed Set**을 두지 않는다. 더 작은 `g`를 발견하면 비용을 갱신하고 다시 후보에 넣을 수 있다. 경로 복원에 사용하는 `cameFrom`도 이때 함께 갱신한다.

`PriorityQueue`는 우선순위가 같은 항목의 삽입 순서를 보장하지 않는다. 따라서 최단 경로가 여러 개인 지도에서는 그중 어느 경로가 반환되는지가 달라질 수 있다. [Microsoft Learn — PriorityQueue 클래스](https://learn.microsoft.com/en-us/dotnet/api/system.collections.generic.priorityqueue-2?view=net-10.0)

## BFS, 다익스트라와 비교

| 알고리즘 | 다음 후보의 선택 기준 | 최단 경로를 보장하는 대표 조건 |
|----|----|----|
| BFS | 시작점에서 이동한 횟수, FIFO 큐 | 모든 간선의 이동 비용이 같다. |
| 다익스트라 | 현재까지의 비용 `g(n)` | 간선 비용이 음수가 아니다. |
| A* | 예상 전체 비용 `g(n) + h(n)` | 음수 간선이 없고, 허용 가능한 휴리스틱과 더 좋은 경로의 재탐색을 사용한다. |
| 탐욕적 최선 우선 탐색 | 남은 비용의 추정값 `h(n)` | 일반적으로 최단 경로를 보장하지 않는다. |

위 비교는 유한한 그래프를 기준으로 한다. 예제처럼 모든 이동 비용이 같은 격자에서는 BFS로도 최단 경로를 구할 수 있다. A*는 목표에 관한 정보를 사용하여 탐색할 후보를 줄이는 데 의미가 있으며, 지도와 휴리스틱에 따라 실제 탐색량은 달라진다.

## 시간 복잡도

**위 예제의 4방향 격자와 일관적인 맨해튼 휴리스틱**을 기준으로, 이동 가능한 칸의 수를 `V`라고 하자.

각 칸의 이웃은 최대 4개이므로 간선 수는 `O(V)`이다. 일관적인 휴리스틱에서는 각 칸을 유효한 후보로 확장할 때 최단 비용이 확정되며, 큐에 남은 오래된 후보를 포함해 삽입과 삭제 횟수도 `O(V)`이다. 힙 기반 우선순위 큐의 연산에 `O(log V)`가 필요하므로 시간 복잡도는 **O(V log V)**, 추가 공간 복잡도는 **O(V)**이다. 딕셔너리 조회와 갱신은 평균 `O(1)`로 계산한다.

이 복잡도를 모든 A* 문제에 그대로 적용해서는 안 된다. 일관적이지 않은 휴리스틱으로 노드를 재확장하거나, 상태 공간 자체가 매우 큰 문제에서는 필요한 탐색량과 메모리가 크게 늘어날 수 있다.

## 주의할 점

- 휴리스틱이 실제 남은 비용을 과대평가하면 최단 경로를 보장할 수 없다.
- 이동 비용이 달라지면 `newG`에 실제 비용을 더하고, 휴리스틱도 같은 비용 단위로 계산해야 한다. 4방향 격자에서는 `맨해튼 거리 × 한 칸의 최소 이동 비용`을 하한으로 사용할 수 있다.
- 대각선 이동을 허용하면 휴리스틱도 다시 선택해야 한다. 예를 들어 대각선과 직선 이동 비용이 모두 `1`일 때 `(0, 0)`에서 `(1, 1)`까지의 실제 비용은 `1`이지만 맨해튼 거리는 `2`여서 과대평가가 된다.
- 목표 방향에 장애물이 많거나 휴리스틱의 추정이 부정확하면 A*도 많은 칸을 탐색할 수 있다.
