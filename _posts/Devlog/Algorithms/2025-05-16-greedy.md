## 개요

**그리디 알고리즘(Greedy Algorithm)**은 매 단계에서 현재 상황에 가장 좋아 보이는 선택을 하고, 이전 선택을 되돌리지 않는 방식이다.

지역적으로 최적인 선택을 반복하기 때문에 구현이 단순하고 빠른 경우가 많지만, 그 선택들이 항상 전체 문제의 최적해를 만든다고 보장되지는 않는다. 따라서 그리디 문제의 핵심은 규칙을 찾는 것보다 **그 규칙이 최적해를 보장하는 이유를 증명하는 것**이다.

## 그리디 알고리즘의 조건

그리디 알고리즘으로 최적해를 구하려면 보통 다음 성질을 확인한다.

| 성질 | 내용 |
|----|----|
| 그리디 선택 속성 | 현재의 최선 선택을 포함하는 최적해가 존재한다. |
| 최적 부분 구조 | 선택 이후 남은 부분 문제의 최적해를 이용해 전체 최적해를 만들 수 있다. |

한 번의 선택이 이후 가능한 선택에 영향을 주더라도, 그 영향을 단순한 새로운 부분 문제로 표현할 수 있어야 한다.

## 증명 방법

그리디 전략이 맞는지 확인할 때 자주 사용하는 방법은 다음과 같다.

### 교환 논증(Exchange Argument)

어떤 최적해가 그리디 선택을 사용하지 않는다고 가정한다. 그 최적해의 선택 하나를 그리디 선택으로 교환해도 결과가 나빠지지 않음을 보이면, 그리디 선택을 포함하는 최적해가 존재한다.

### 앞서 나가기(Stays Ahead)

그리디 해가 매 단계에서 다른 어떤 해보다 뒤처지지 않음을 보인다. 각 단계의 결과를 비교할 수 있는 문제에서 유용하다.

### 귀류법

그리디 선택으로 만든 답보다 더 좋은 답이 존재한다고 가정한 뒤, 그 가정이 선택 규칙이나 문제 조건과 모순됨을 보인다.

## 예시: 활동 선택 문제

서로 겹치지 않는 활동을 최대한 많이 선택해야 한다고 가정한다. 각 활동에는 시작 시각과 종료 시각이 있다.

이 문제에서는 **종료 시각이 가장 빠른 활동부터 선택**한다. 가장 빨리 끝나는 활동은 이후 활동을 선택할 수 있는 시간을 가장 많이 남긴다.

```cs
public static List<(int Start, int End)> SelectActivities(
    IEnumerable<(int Start, int End)> activities)
{
    var sorted = activities.OrderBy(activity => activity.End).ToList();
    var selected = new List<(int Start, int End)>();
    int lastEnd = int.MinValue;

    foreach (var activity in sorted)
    {
        if (activity.Start < lastEnd)
            continue;

        selected.Add(activity);
        lastEnd = activity.End;
    }

    return selected;
}
```

정렬에 `O(n log n)`, 선택에 `O(n)`이 필요하므로 전체 시간 복잡도는 **O(n log n)**이다.

교환 논증으로도 확인할 수 있다. 임의의 최적해에서 첫 활동을 가장 빨리 끝나는 활동으로 바꾸어도 이후 활동을 위한 시간이 줄어들지 않는다. 따라서 가장 빨리 끝나는 활동을 포함하는 최적해가 항상 존재한다.

## 그리디가 실패하는 경우

동전이 `1`, `3`, `4`이고 금액 `6`을 만들어야 한다고 가정한다.

가장 큰 동전부터 고르면 `4 + 1 + 1`로 3개가 필요하지만, 최적해는 `3 + 3`으로 2개이다. 일반적인 동전 집합에서는 현재 가장 큰 동전을 선택하는 규칙이 최적해를 보장하지 않는다.

따라서 다음을 확인하지 않고 단순히 가장 크거나 작은 값을 고르는 것은 그리디 알고리즘의 근거가 될 수 없다.

- 현재 선택을 다른 최적해의 선택과 교환해도 손해가 없는가?
- 현재 선택이 미래의 더 좋은 선택을 막지는 않는가?
- 작은 반례를 직접 만들어 보았는가?
- 최적값뿐 아니라 선택 결과 자체도 문제의 모든 조건을 만족하는가?
