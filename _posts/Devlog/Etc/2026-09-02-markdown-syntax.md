## 개요

마크다운(Markdown)은 간단한 기호를 이용해 문서의 구조와 서식을 표현하는 문법이다.

별도의 편집 도구 없이 일반 텍스트로 작성할 수 있으며, README, 블로그 포스트, 문서 작성 등에 자주 사용한다. 이 글에서는 자주 사용하는 마크다운 문법과 간단한 예시를 정리한다.

> 마크다운을 처리하는 도구에 따라 지원하는 문법이나 결과가 조금씩 다를 수 있다. 이 블로그는 Jekyll의 Kramdown과 GFM(GitHub Flavored Markdown)을 기준으로 작성한다.

## 제목

문장 앞에 `#`을 붙여 제목을 만든다. `#`의 개수가 많아질수록 제목의 단계가 낮아지며, `#` 뒤에는 공백을 한 칸 넣는다.

```markdown
# 제목 1
## 제목 2
### 제목 3
#### 제목 4
##### 제목 5
###### 제목 6
```

문서 전체 제목은 보통 1단계 제목을 사용하고, 본문은 2단계와 3단계 제목으로 구분한다.

## 문단과 줄바꿈

빈 줄을 하나 넣으면 새로운 문단이 만들어진다.

```markdown
첫 번째 문단입니다.

두 번째 문단입니다.
```

같은 문단 안에서 강제로 줄을 바꾸려면 문장 끝에 공백을 두 칸 넣거나 `<br>` 태그를 사용한다.

```markdown
첫 번째 줄입니다.  
두 번째 줄입니다.

세 번째 줄입니다.<br>
네 번째 줄입니다.
```

## 글자 꾸미기

별표(`*`), 밑줄(`_`), 물결표(`~`)를 이용해 글자를 강조하거나 취소선을 표시한다.

```markdown
*기울임* 또는 _기울임_

**굵게** 또는 __굵게__

***굵은 기울임***

~~취소선~~
```

표시 결과는 다음과 같다.

*기울임* 또는 _기울임_

**굵게** 또는 __굵게__

***굵은 기울임***

~~취소선~~

## 인용문

문장 앞에 `>`를 붙여 인용문을 만든다. `>`를 여러 번 사용하면 인용문을 중첩할 수 있다.

```markdown
> 첫 번째 인용문입니다.
>
> > 중첩된 인용문입니다.
```

표시 결과는 다음과 같다.

> 첫 번째 인용문입니다.
>
> > 중첩된 인용문입니다.

## 목록

### 순서가 없는 목록

문장 앞에 `-`, `*`, `+` 중 하나를 붙인다. 하위 항목은 공백을 넣어 들여쓴다.

```markdown
- 사과
- 바나나
    - 노란 바나나
    - 초록 바나나
- 오렌지
```

표시 결과는 다음과 같다.

- 사과
- 바나나
    - 노란 바나나
    - 초록 바나나
- 오렌지

### 순서가 있는 목록

숫자와 마침표를 사용한다. 실제 번호와 관계없이 `1.`만 반복해도 렌더링할 때 순서대로 번호가 표시된다.

```markdown
1. 저장소를 내려받는다.
2. 파일을 수정한다.
3. 변경 내용을 확인한다.
```

표시 결과는 다음과 같다.

1. 저장소를 내려받는다.
2. 파일을 수정한다.
3. 변경 내용을 확인한다.

### 체크박스

목록 기호 뒤에 `[ ]`를 쓰면 할 일 목록을 만들 수 있다. 완료한 항목은 `[x]`로 표시한다.

```markdown
- [x] 글 주제 정하기
- [x] 초안 작성하기
- [ ] 맞춤법 확인하기
```

표시 결과는 다음과 같다.

- [x] 글 주제 정하기
- [x] 초안 작성하기
- [ ] 맞춤법 확인하기

## 링크와 이미지

### 링크

대괄호에는 화면에 표시할 문구를, 소괄호에는 이동할 주소를 넣는다. 링크에 마우스를 올렸을 때 설명을 표시하려면 주소 뒤에 제목을 추가한다.

```markdown
[Pioh Archive](/)

[Pioh Archive](/ "블로그 홈으로 이동")
```

표시 결과는 다음과 같다.

[Pioh Archive](/)

주소를 그대로 링크로 표시할 때는 꺾쇠괄호를 사용한다.

```markdown
<https://devpioh.github.io>
```

### 이미지

링크 문법 앞에 느낌표(`!`)를 붙인다. 이미지가 표시되지 않을 때를 위해 대체 텍스트를 작성하는 것이 좋다.

```markdown
![이미지 설명](/assets/images/sample.png)

![이미지 설명](/assets/images/sample.png "이미지 제목")
```

외부 이미지 주소뿐 아니라 프로젝트 내부의 상대 경로도 사용할 수 있다. 실제 문서에서는 예시 경로를 이미지가 저장된 경로로 바꿔야 한다.

## 코드

### 인라인 코드

짧은 코드나 파일 이름, 명령어는 백틱 한 개로 감싼다.

```markdown
`git status` 명령어로 변경된 파일을 확인한다.
```

표시 결과는 다음과 같다.

`git status` 명령어로 변경된 파일을 확인한다.

### 코드 블록

여러 줄의 코드는 백틱 세 개로 감싼다. 시작 백틱 뒤에 언어 이름을 적으면 문법 강조를 적용할 수 있다.

~~~markdown
```csharp
public class Program
{
    public static void Main()
    {
        Console.WriteLine("Hello, Markdown!");
    }
}
```
~~~

표시 결과는 다음과 같다.

```csharp
public class Program
{
    public static void Main()
    {
        Console.WriteLine("Hello, Markdown!");
    }
}
```

## 구분선

하이픈, 별표 또는 밑줄을 세 개 이상 연속해서 입력한다. 앞뒤에 빈 줄을 넣으면 다른 문법과 혼동되는 것을 줄일 수 있다.

```markdown
---

***

___
```

표시 결과는 다음과 같다.

---

## 표

파이프(`|`)와 하이픈(`-`)을 이용해 표를 만든다. 두 번째 줄의 콜론(`:`) 위치로 열의 정렬 방향을 지정할 수 있다.

```markdown
| 문법 | 기호 | 용도 |
|:---|:---:|---:|
| 굵게 | `**` | 강조 |
| 인용문 | `>` | 인용 |
| 링크 | `[]()` | 페이지 이동 |
```

- `:---` : 왼쪽 정렬
- `:---:` : 가운데 정렬
- `---:` : 오른쪽 정렬

표시 결과는 다음과 같다.

| 문법 | 기호 | 용도 |
|:---|:---:|---:|
| 굵게 | `**` | 강조 |
| 인용문 | `>` | 인용 |
| 링크 | `[]()` | 페이지 이동 |

## 각주

본문에 각주 표시를 넣고 문서의 다른 위치에 설명을 작성할 수 있다. 각주 이름은 숫자뿐 아니라 문자도 사용할 수 있다.

```markdown
마크다운은 일반 텍스트 기반의 문법이다.[^markdown]

[^markdown]: John Gruber가 만든 경량 마크업 언어이다.
```

## 특수문자 그대로 표시하기

마크다운 문법에 사용되는 기호를 그대로 표시하려면 기호 앞에 역슬래시(`\`)를 붙인다.

```markdown
\*이 문장은 기울임으로 표시되지 않습니다.\*

\# 이 문장은 제목으로 표시되지 않습니다.
```

표시 결과는 다음과 같다.

\*이 문장은 기울임으로 표시되지 않습니다.\*

\# 이 문장은 제목으로 표시되지 않습니다.

## 주석

HTML 주석 문법을 사용하면 작성한 내용이 최종 화면에 표시되지 않는다. 메모를 남기거나 임시로 내용을 숨길 때 유용하다.

```markdown
<!-- 이 내용은 화면에 표시되지 않습니다. -->
```

## 작성할 때 알아두면 좋은 점

1. 제목 기호, 목록 기호 뒤에는 공백을 한 칸 넣는다.
2. 제목, 목록, 코드 블록의 앞뒤에는 빈 줄을 넣으면 문법이 안정적으로 적용된다.
3. 같은 문서에서는 제목 단계와 목록 기호를 일관되게 사용한다.
4. 이미지에는 내용을 설명하는 대체 텍스트를 작성한다.
5. 마크다운 도구마다 지원 범위가 다르므로 게시 전에 미리보기로 결과를 확인한다.

## 한 번에 보는 예시

다음은 앞에서 살펴본 문법을 조합한 간단한 작업 기록이다.

~~~markdown
## 오늘의 작업

> 목표: 마크다운 문법 정리하기

- [x] 제목 작성
- [x] 예제 코드 추가
- [ ] 최종 검토

자세한 내용은 [문서 페이지](/)에서 확인한다.

```bash
git status
```
~~~

## 프론트 매터

프론트 매터(Front Matter)는 파일의 맨 앞에서 제목, 작성일, 태그 같은 메타데이터를 기록하는 영역이다. 프론트 매터 자체는 마크다운이나 YAML의 고유 문법이 아니며, 여러 문서 도구가 구분선 사이의 YAML 데이터를 읽는 방식이다.

일반적으로 하이픈 세 개(`---`) 사이에 YAML을 작성하고, 두 번째 구분선 다음부터 마크다운 본문을 작성한다. 각 항목의 이름과 용도는 YAML이 정하는 것이 아니라 해당 파일을 사용하는 프로그램이 정한다.

```yaml
---
title: "Markdown 문법 정리"
published: true
date: "2026-09-02"
tags:
    - markdown
    - 마크다운
    - 문법
author:
    name: Pioh
    profile: https://github.com/devpioh
---
```

### 키와 값

YAML의 기본 구조는 `키: 값`이다. 콜론 뒤에는 공백을 한 칸 넣는다.

```yaml
title: "Markdown 문법 정리"
language: ko
```

키는 데이터를 구분하는 이름이고 값은 실제 데이터다. YAML에서 키와 값의 묶음을 매핑(Mapping)이라고 한다.

### 기본 자료형

문자열, 숫자, 불리언, 빈 값 등을 표현할 수 있다.

```yaml
title: "YAML 문법 정리"  # 문자열
order: 1                # 정수
score: 4.5              # 실수
published: true         # 불리언
description: null       # 빈 값
```

`true`, `false`, `null`처럼 다른 자료형으로 해석될 수 있는 단어를 문자열로 사용하려면 따옴표로 감싼다. 날짜도 처리 도구에 따라 해석 방식이 다를 수 있으므로 문자열로 유지하려면 따옴표를 사용한다.

```yaml
answer: "true"
date: "2026-09-02"
```

### 목록

목록은 각 항목 앞에 하이픈과 공백(`- `)을 붙여 작성한다. 대괄호를 사용해 한 줄로 표현할 수도 있다.

```yaml
# 블록 형식
tags:
    - markdown
    - yaml
    - blog

# 한 줄 형식
tags: [markdown, yaml, blog]
```

두 형식은 같은 목록을 나타낸다. 항목이 많거나 자주 수정된다면 블록 형식이 읽기 편하다.

### 중첩 구조

공백으로 들여쓰기하면 한 항목 아래에 다른 매핑이나 목록을 넣을 수 있다.

```yaml
author:
    name: Pioh
    links:
        - name: GitHub
          url: https://github.com/devpioh
        - name: Blog
          url: https://devpioh.github.io
```

같은 단계의 항목은 들여쓰기 깊이를 동일하게 맞춰야 한다. 들여쓰기 너비는 자유롭게 정할 수 있지만, 한 문서 안에서는 일관되게 사용하는 것이 좋다.

### 여러 줄 문자열

파이프(`|`)는 줄바꿈을 유지하고, 꺾쇠(`>`)는 이어지는 줄을 하나의 문장처럼 합친다.

```yaml
# 줄바꿈 유지
description: |
    첫 번째 줄입니다.
    두 번째 줄입니다.

# 줄바꿈을 공백으로 변경
summary: >
    여러 줄로 작성하지만
    하나의 문장처럼 처리합니다.
```

### 주석

샵 기호(`#`) 뒤의 내용은 주석으로 처리된다. 값에 `#`을 문자로 포함해야 한다면 따옴표로 감싸는 것이 안전하다.

```yaml
published: true       # 공개 여부
color: "#ffffff"      # 따옴표 안의 #은 문자열의 일부
```

### 작성할 때 주의할 점

1. 들여쓰기에는 탭 대신 공백을 사용한다.
2. 같은 단계의 키는 중복하지 않도록 작성한다.
3. 콜론(`:`), 샵 기호(`#`) 등 특별한 의미가 있는 문자가 값에 포함되면 따옴표로 감싼다.
4. 프론트 매터에서 사용할 수 있는 키와 실제 동작은 문서를 처리하는 프로그램의 설명을 확인한다.
